# Project Bootstrap Route

## Route

1. Read root/project `AGENTS.md`, quick start and technical preferences.
2. Detect or request only genuinely missing configuration: engine/version, language/authoring approach, project stage and optional framework.
3. Inspect existing project source/tests/config before assuming a blank template.
4. Select the nearest provider-neutral shared skill/rule; do not create a new skill if an existing one covers the workflow.
5. If Unity uses Loomlight Flux, route framework-specific claims to installed Flux/package instructions; otherwise keep generic Unity first-class.
6. Define engine-specific validation from actual project configuration. Do not invent a universal build/test command.
7. Identify owner approval gates for phase changes, releases, destructive work or other high-impact decisions.
8. Return the smallest next implementation slice and evidence required to call it complete.

## Output

Engine/version, stage, framework status, selected skill(s), implementation owner, automated validation, manual engine validation, owner gates and unresolved configuration.
